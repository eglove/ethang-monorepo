You open a tab, pick a model, and start working. The reply streams, the plan takes shape, the code lands in the right file. Then a command hangs and the run stalls with it. A context window fills and the session dies mid-thought. A tab closes and takes the whole working memory of the project with it. None of that is the model failing. It is the scaffolding around the model failing, and the scaffolding is where these products are actually built.

eThang Agent begins from that inversion. It is an agent harness for Windows: the scaffolding an AI model acts through — agent loop, tool dispatch, session persistence, a desktop shell — while the model supplies the decisions. The core is .NET 10 behind an Avalonia frontend, with provider-neutral contracts over OpenRouter (https://openrouter.ai/) and z.ai (https://z.ai/). The premise is unglamorous and correct: intelligence is now the cheap part. Continuity, discipline, and a small blast radius are not.

## One tool, made general

Most harnesses hand the model a long menu of narrow utilities — one for searching, one for editing, one for every special case. Each utility is a fresh place to be surprised. eThang Agent hands the model one general instrument instead: `exec`, which compiles and runs a C# program in-process through Roslyn. There is no shell intermediary to inject characters the model never typed; each argument becomes one token of a native command line, re-parsed with Windows argv rules so the process receives what the model intended. File system work, LINQ queries over the workspace, external commands, tool calls from inside the script — all of it is the same surface.

The loop inside the tool reads like its contract — parse, reject, and only then act:

```csharp
Result<ExecToolInput> parsed = ExecToolInput.Create(input.JsonArguments);
if (!parsed.IsSuccess)
{
  return Task.FromResult(new ToolResult(
      $"Error [{parsed.Error.Code}]: {parsed.Error.Message}", true));
}

Result<ToolCallEnvelope> budget = ToolCallEnvelopeParser.Parse(input.Name, input.JsonArguments);
```

A malformed call never reaches the compiler. It comes back as a typed error naming the rule it broke, and the model corrects the call from the error's own words.

The details show the attitude. When output runs past 50,000 characters, nothing is dropped: both ends are preserved and the full text is saved as an artifact the model can read back with a follow-up call.

## A budget on every action

That budget is the harness's spine. Every tool call carries a mandatory `timeoutSeconds`, a whole number between 1 and 3600, declared in every tool definition as a required parameter with its floor written where the parser can enforce it:

```csharp
new ToolParameter(ToolTimeout.ParameterName, ToolParameterType.WholeNumber,
    ToolTimeout.ParameterDescription, Minimum: 1)
```

Exceed it and the call fails as `Error [ToolTimeout]` — a visible error, not a hang, and the model gets a fresh decision: re-issue with a larger budget if the work genuinely needs it, or find another route. Nothing spins until a human notices the spinning. The agent's own loop runs uncapped until it answers without tool calls, and cancellation is honored at every turn boundary, so Stop means stop.

A stuck call is the classic way agent runs die quietly. Here the failure has a name, a type, and a recovery path — which is the difference between a tool and a liability.

## Memory that survives the tab

Sessions persist to an app-owned SQLite database through versioned migrations: every message, every tool call and result, in order. The Sessions menu lists what exists and resumes one deliberately, replaying the full transcript on its original provider and workspace. `memory.recall` searches prior transcripts for decisions, errors, and context from earlier work. A separate curated store holds durable facts — conventions, failures worth not repeating — as versioned, tagged entries the model can search before it assumes.

The API keys that drive it all sit in the same database, DPAPI-encrypted with current-user scope: plaintext keys never touch disk, and only the Windows user who wrote them can read them back. The boring choices are the trust choices.

## The safety ledger

Power concentrates quickly in an agent, so the harness rations it on purpose. The database tools are read-only — a statement that writes, chains, or attaches a foreign database is rejected outright. `git_commit` validates every message against the user's chosen commit style and returns a typed error naming the exact rule when the type is wrong or an emoji sneaks in where it is forbidden.

`write` refuses to clobber an existing file: the call fails if the file exists unless overwrite is exactly true — it will never silently replace anything. The gate is not policy prose; it is a declared parameter:

```csharp
new ToolParameter("overwrite", ToolParameterType.Flag,
    "Optional. Defaults to refusing replacement of an existing file; true replaces it.")
```

Create-only by default. Replacement is a decision the model has to state out loud.

Delegation stays a tree, not a flood: sub-agents spawn with a hard depth limit and concurrency caps, and each one inherits the same ledger. Input typed mid-turn is never dropped — it waits in a session inbox and reaches the model at the next safe point, never splitting a tool call from its results. Stop hard-cancels the turn and every child, and half-finished tool batches are repaired in place so the conversation history stays valid for whatever comes next.

## What it will not pretend

The harness is honest about the edges. Capability that a provider endpoint does not expose is not simulated into existence: z.ai's live search, page reading, image generation, OCR, and audio transcription appear only on the endpoint that actually offers them. A stream cut off without its terminator is a named error, never a silently truncated answer. Length-capped turns continue automatically, the partial answer kept, and the cap itself surfaced as a visible error if it runs out.

Context gets the same treatment. The status bar shows live utilization; when it crosses 80% at a turn boundary, the oldest conversation is summarized by a compaction model and replaced by that handoff, and the session keeps going instead of dying at the window. Compacted sessions persist and resume like any other.

## The draft on the wall

The ambitions are kept in the open, in the project's own words: a fullscreen IDE — "by every definition," inspired by JetBrains rather than a chat box or a VS Code clone — where the harness's views grow real engineering surface. A file explorer with live syntax highlighting, watched by a file watcher rather than polled. A git view with realtime diffing, pull-request management, and CI status. A static analysis view hunting duplicate code, dead code, code smells, and security vulnerabilities — with lint and formatter autofixes that feed errors straight back to the agent. A kanban view where the agent's plan and todos render as cards, updating in realtime. A database view over the app's own SQLite store, live. An agent view where multiple windows stream several runs at once. And an AI debugging plan that goes where humans rarely look: running projects on a debug port and analyzing internal state through the Debug Adapter Protocol, so the model reads the program's insides instead of guessing from stack traces.

The surrounding machinery gets the same ambition. A background maintenance process polls for hung agents — agents that stopped without finishing — and restarts or reprompts them, with deadlock detection that kills the deadlock and reports the kill back to the model. MCP support. Local models through LM Studio and Ollama, queried and listed like any hosted provider. Agents that trigger their own context compaction when a milestone completes or the conversation turns redundant. Even formal methods: temporary TLA+ specifications written and checked to validate concurrency plans during the planning phase.

The same roadmap subtracts as readily as it adds. The general file-search tool is slated for deletion, on the grounds that in-process scripting already covers the need. Structured clarifying prompts go too, so the model formats its own questions. A harness confident enough in one general instrument to keep removing the special cases around it is the trajectory worth watching.

The scaffolding is not a static frame around a model; it is the actual product, and this one is being shaped toward an environment where the machinery stays inspectable even as it grows.

## The part that has to tell the truth

Every harness faces the same trade. Hide the machinery and the model feels magical; keep the machinery legible and the work becomes trustworthy. eThang Agent chooses legible — budgets on every action, errors with names and recovery paths, memory you can resume, a ledger of what the agent may not do. The model is the easy part. The harness is the part that has to tell the truth.
