Every AI coding harness makes the same promise — point a model at your code and let it work — but the scaffolding — the scaffolding an AI model acts through — differs sharply, and the differences decide reliability. [eThang Agent](https://github.com/eglove/ethang-agent) is an open-source, Windows-native harness built on .NET 10 and Avalonia, and this post compares it with the tools most developers actually use: **Claude Code** and **OpenAI Codex** (terminal-native agents from the model labs), **Gemini CLI** (Google's open-source terminal agent), **Cursor** and **Windsurf** (IDE-forked experiences), and **OpenCode** (the popular open-source terminal alternative).

The framework for comparison is deliberately practical. A harness has five jobs: structure the agent loop, expose tools, reach models, persist work, and test its own machinery. Different tools make different trade-offs on each axis, and none dominates all five.

## Loop and interface: terminal, IDE fork, or desktop shell

Where the harness *lives* shapes everything else. Claude Code, Codex, Gemini CLI, and OpenCode are terminal-first: the conversation is a REPL, the UI is text. Cursor and Windsurf embed the agent in a VS Code fork, so chat and editor share a window. eThang Agent takes a third path — a dedicated Avalonia desktop app, no terminal dependency, no editor fork to track upstream.

The desktop choice buys UI capabilities the terminals cannot easily match: streamed responses with reasoning rendered readably, expandable cards for every tool call and result, a Sessions menu that resumes any past conversation with its full transcript replayed, and a status bar with live context utilization:

The trade-off is ecosystem. VS Code forks inherit thousands of extensions; terminals inherit scriptability and SSH workflows. A desktop shell has to build more itself, and what it builds is only available inside it.

## Architecture: what the codebase looks like

Most of the field ships as one application codebase. eThang Agent is structured as one project per bounded context — `eThangAgent.Tool.Domain` for tool contracts, plus conversation, agent, memory, skills, state, and capability contexts — plus an anti-corruption layer (ACL) per external dependency: `eThangAgent.Roslyn.ACL` for script execution, separate OpenRouter and z.ai ACLs behind shared wire contracts, `eThangAgent.FileSystem.ACL` and `eThangAgent.Storage.ACL` for files and SQLite, all wired host-agnostically in `eThangAgent.Composition` and hosted by `eThangAgent.Desktop`.

Domains do not know Roslyn, HTTP, or SQLite exist. Compared with a typical single-project TypeScript agent, this buys isolation rather than speed of hacking: external providers can be faked or swapped without touching conversation logic, and each context tests in isolation. The cost is ceremony — eighteen projects where a competitor might ship four.

## Tools: menus versus a general instrument

Every harness gives the model file and shell tools; they differ in shape. Terminal agents expose a flat menu of command-line tools. VS Code forks lean on editor primitives (LSP diagnostics, built-in search). eThang Agent exposes discrete tools — read, write, edit, git_status, working_diff, db_schema, db_query, todo, curated memory, sub-agent spawning — each a class implementing one `ITool` interface with a declarative, validated `ToolDefinition`, alongside one deliberately general tool: `exec`, in-process C# scripting through Roslyn.

Every tool follows the same parse-reject-run shape. From `ExecTool.cs`:

```csharp
Result<ExecToolInput> parsed = ExecToolInput.Create(input.JsonArguments);
if (!parsed.IsSuccess)
{
  return Task.FromResult(new ToolResult(
      $"Error [{parsed.Error.Code}]: {parsed.Error.Message}", true));
}

Result<ToolCallEnvelope> budget = ToolCallEnvelopeParser.Parse(input.Name, input.JsonArguments);
```

Every call carries a mandatory `timeoutSeconds`, a whole number from 1 to 3600 with its floor declared `Minimum: 1` on the parameter itself — enforced by the envelope parser, not by convention. Exceed it and the call fails as `Error [ToolTimeout]` — recoverable by re-issuing with a larger budget or choosing another route, never a silent hang. The overwrite gate on `write` is the same philosophy: the call fails if the file exists unless overwrite is exactly true — it will never silently replace anything:

```csharp
new ToolParameter("overwrite", ToolParameterType.Flag,
    "Optional. Defaults to refusing replacement of an existing file; true replaces it.")
```

Where eThang Agent genuinely departs from the field is composition. The named tools are exposed *inside* the exec environment, so one script can read, patch, test, and conditionally commit — branching no linear tool-call loop expresses cleanly:

```csharp
var head = Tools.read(new { path = "src/App.ts", startLine = 1, endLine = 50 });
Tools.edit(new { path = "src/App.ts", old = "render()", replacement = "renderApp()", occurrences = 1 });
var tests = Shell("dotnet", "test");
if (tests.ExitCode == 0)
  Tools.Invoke("git_commit", new { type = "fix", description = "mount App once" });
```

Cursor's Composer and the terminal agents' plan modes orchestrate multi-step work too, but through the harness's own loop, one tool call per round trip. In-process scripting makes the *model* the orchestrator inside a single budgeted call. The transcript renders each call and result as expandable cards, so long scripts stay inspectable:

## Model access: bundled, proprietary, or provider-neutral

The deepest structural difference is the model relationship. Claude Code is built around Anthropic models (and now third-party via its own gateway); Codex around OpenAI's; Cursor and Windsurf bundle hosted models plus bring-your-key options. Gemini CLI and OpenCode are open and multi-provider. eThang Agent is provider-neutral by architecture: provider-neutral contracts with one ACL per provider, an agent tab bound to [OpenRouter](https://openrouter.ai/) or [z.ai](https://z.ai/) for its lifetime — mirroring how terminal CLIs treat each provider as a distinct world rather than papering over differences with a merged abstraction.

Two OpenRouter behaviors stand out against the field. Auto mode is a two-stage LLM pipeline that categorizes the prompt and selects the best model from the live catalog — re-run every tenth message so the model tracks the evolving task; sub-agent spawns pick their own models from task prompts. And the harness refuses capability theater: z.ai's web search, OCR, image generation, and transcription exist only on the endpoint that offers them — never simulated elsewhere.

## Context and persistence

Context handling is where agents actually die, and the field splits. Claude Code auto-compacts with a summarized handoff; Gemini CLI compacts at its threshold; Cursor leans on editor context and manual control. eThang Agent's status bar shows live utilization, and when it crosses 80% at a turn boundary, the oldest conversation is summarized by a configurable compaction model and replaced by that handoff — the session continues, and compacted sessions persist and resume like any other.

Persistence goes further than transcript files. One app-owned SQLite database holds full transcripts (tool calls and results included), durable workspace state, curated versioned memory, and the agent graph. The database groups along the same bounded-context lines as the code:

Sessions resume from the menu with full replay; `memory.recall` searches prior transcripts; curated memory is versioned and tagged. API keys sit in the same database, DPAPI-encrypted with current-user scope. Most competitors keep sessions as local JSONL or workspace files — eThang Agent treats its database as the product's memory, with a read-only inspection surface (`db_schema`, `db_query`) the model itself can query.

## Ecosystem reality check

Honesty requires the other column. Claude Code and Codex have the strongest frontier models behind them, and their harnesses are tuned to those models' quirks. Cursor and Windsurf have years of IDE polish, tab-completion trained on repositories, and enormous user bases — eThang Agent's UI work is younger and its community is one developer plus contributors. OpenCode is further along as a community project with dozens of contributors. eThang Agent is Windows-first — a deliberate choice, but a narrowing one, since the field's terminals and forks are cross-platform. Sub-agent orchestration exists here with a hard depth limit and concurrency caps, but Claude Code's and OpenCode's agent ecosystems are richer in practice.

What eThang Agent offers that the field does not, in one paragraph: a desktop shell rather than terminal or editor fork; a strict bounded-context architecture with ACL-per-dependency; validated tool contracts with hard budgets on every call (`Error [ToolTimeout]` as a first-class error); in-process composition of the named tools through Roslyn scripting; provider-neutral model access with honest capability boundaries and an auto-selection pipeline; and a SQLite-centric persistence model with resume, recall, and curated memory. Plus a roadmap aimed at the IDE-shaped gap — a fullscreen JetBrains-inspired IDE with a file explorer with live syntax highlighting, realtime git diffing with PR and CI views, static analysis whose autofixes feed errors back to the agent, realtime kanban and database views, MCP support, local providers like LM Studio and Ollama, agents that run projects on a debug port and read program state through the Debug Adapter Protocol, a maintenance process that polls for hung agents, and formal TLA+ validation of concurrency plans.

## Takeaway

The harness, not the model, is where these products differentiate — and the comparison proves it. Claude Code wins on model access; Cursor and Windsurf on editor ecosystem; Gemini CLI and OpenCode on openness and community. eThang Agent bets on architecture: structured contexts, validated tools, honest provider boundaries, durable memory. If you want to see how the bets play out, the repository is open — pull on any thread.
